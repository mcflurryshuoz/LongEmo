# E06: Azure GPT-6 full episode benchmark

This is a separate provider run of the frozen event-graph method. E03/E04/E05 OpenRouter manifests and perception outputs remain intact. E06 rebuilds perception using Azure; only matching, question-independent Gemini audio caches may be copied. Each imported audio cache is fingerprint-validated before reuse and listed in imported_audio.json; its original cost belongs to E03.

Dataset: LongEmoBench revision bb1933541008571883fa1eec1e7bd44d94b6ad2b, all 141 episode videos and 558 questions (8,342 twenty-second windows). V16 is a development video. The remaining queue is ordered by duration, independently of labels and scores. Incomplete coverage is never a full benchmark result.

Perception, planning, answers and unchanged official judgments use Azure deployment gpt-6-astra, API 2025-01-01-preview, reasoning effort medium, maximum completion 8,192 tokens. A real request returned gpt-6-astra-2026-09-03. Authentication refreshes the already-authorized default Azure CLI context on g450; credentials are not written to manifests or Git. Audio uses OpenRouter google/gemini-3.8-flash; embeddings use google/gemini-embedding-2 at 3,072 dimensions. Retrieval remains semantic plus dense RRF and event-graph expansion, top-k 12 per route, 48,000 evidence characters, no inspection.

Start with 16 videos concurrently and two answer/judge workers per video. A shared SQLite admission ledger limits this experiment to 250,000 tokens/minute, 120 requests/minute and 24 simultaneous Azure requests. These are operational starting values, below the deployment's reported 1M token/minute and 1,000 request/minute quota because other jobs share the deployment. Actual usage refunds reservations. Shared Retry-After cooldown and bounded retries handle 429 and transient server errors; permissions fail immediately. A private token is refreshed before admission. Every HTTP attempt has a separate token/latency/status ledger, including successful responses later rejected by schema validation. Azure billing is unknown without billing export, not zero.

The first wave must produce a complete graph/answer/official-score result before extending the queue. Failed videos can retry once from validated checkpoints. Credit exhaustion or three videos with exhausted retries pause further scheduling; active jobs retain their progress. Existing successful predictions and the earliest successful official judgment are reused. Low scores are never selectively rescored. No direct-baseline claim is part of this run, and the same-model judge limitation remains.

Implementation is frozen in a detached worktree on g450 before execution. Runtime output: /mnt/data1/zyf/LongEmo-runtime/runs/azure_gpt6_full_v1. Main controls: status.json, launch.json, launch_settings.json, video_attempts.jsonl, metrics.json, summary.md and azure_transport/*.jsonl. The full denominator always stays 558. Live limiter settings are in /mnt/data1/zyf/LongEmo-runtime/limits/azure_gpt6.json; concurrency/limits changes must be recorded as operational changes, without altering semantic manifests.

The launch.json contains the exact resumable command. Run it from /mnt/data1/zyf/LongEmo-azure-e06 with the same environment paths, API version and CLI context. API secrets stay in the pre-existing private resource file. The run lock refuses overlapping resumes. Use experiments.zyf.azure_status for safe progress snapshots and experiments.zyf.analyze_full for completed score/retrieval analysis. Full-benchmark improvement decisions require the completed error distribution; the prior two-question 87.5% smoke result is not comparable evidence.
