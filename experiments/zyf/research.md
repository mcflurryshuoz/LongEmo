# LongEmo 相关方法调研与取舍

检索截止：2026-09-16。使用论文原文、作者项目/代码页和官方 API 文档。对 WorldMM、AffectSeek、MAGIC-Video 查看了方法或消融相关正文段落；其他条目主要核对摘要、论文信息及作者页面。本次没有运行或完整复现这些方法，也不是穷尽性文献综述。

以下将“原文方法”与“对 LongEmo 的建议”分开。跨论文分数的模型、数据、输入和预算不同，不据此排列统一排行榜。实施方案见 [plan.md](plan.md)。

## 1. 调研得到的主要判断

两阶段路线合理：长视频的覆盖和情感线索细节需要分开处理，问答时再读取所需证据。但普通 caption → 图谱 → 检索已是拥挤方向。对 LongEmo 更值得测试的是：**局部情感线索不丢失，人物与情绪对象不混淆，跨段状态不被错误覆盖，检索能覆盖全局比较/轨迹/计数需要的证据**。

过去的长视频方法主要回答动作、物体、地点、时间及事实关系问题，迁移到情感任务需要额外处理语气、听者反应、混合情绪和人物对事情的理解。相反，情感专用模型擅长短片或对话片段，长时间人物追踪与全片检索并不会自动随之获得。这个判断是基于下面各方法任务设置的综合推断，不是 LongEmo 上已验证的结果。

## 2. 长视频推理方法

| 方法与时间 | 原文核心机制 | 对本项目的启发/限制（本轮判断） |
|---|---|---|
| [LLoVi：A Simple LLM Framework for Long-Range Video Question-Answering](https://github.com/CeeZh/LLoVi)，2024 | 将片段描述交给 LLM，形成简单的长视频问答框架；作者提供 caption 和实验代码 | 必须有“同感知内容 + 简单文本问答/RAG”的强基线，否则不能知道图是否必要 |
| [MovieChat](https://github.com/fil-mp/LongVideoUnderstanding)，CVPR 2024 | 从稠密视觉 token 转为稀疏记忆，支持长视频；官方另有 OneVision 版本 | 可作压缩记忆系统对照；不同版本/骨干必须记录，不能把其分数差只归因于有无图 |
| [VideoAgent](https://arxiv.org/abs/2403.10517)，2024 | LLM 迭代决定要取得哪些视觉信息，借助视觉语言工具检索、理解 | 工具调用与主动选片很早已有；情感方法需说明它选片依据和状态维护的区别 |
| [VideoTree](https://arxiv.org/abs/2405.19209)，CVPR 2025 | query-adaptive 的层次树，逐步选取相关帧，以粗到细的信息支持推理 | 可借鉴多尺度导航；题目驱动的表示构建成本不能算成完全可复用的基础构建 |
| [LongVILA](https://arxiv.org/abs/2408.10188)，2024/ICLR 2025 | 从算法和系统共同扩展长上下文视频语言模型 | 表明大上下文是另一条路线；本项目先用现有原生长视频能力做强基线，无需优先自己训练长上下文骨干 |
| [VideoRAG：Retrieval-Augmented Generation with Extreme Long-Context Videos](https://arxiv.org/abs/2502.01549)，2025 | 图式文本知识与多模态上下文双通道，支持超长视频和跨视频关系检索 | 借鉴文字/原始视觉双入口；本项目按视频隔离记忆，不能让跨片知识污染独立样本 |
| [M3-Agent](https://arxiv.org/abs/2508.09736)，2025 | 实体中心的多模态长期记忆，情景/语义记忆更新，多轮检索推理；包含 RL 训练 | 不能将“实体记忆、可更新、多轮问答”当作新意；prompt 版改造要与原训练系统区分 |
| [WorldMM](https://arxiv.org/abs/2512.02425)，2025；作者项目标注 CVPR 2026 Highlight | 多尺度情景记忆、不断整合的语义图、视觉记忆，以及自适应检索 | 最重要的通用记忆近邻之一；应比较它的记忆组织与情绪对象/状态更新，而非只比较旧 caption 基线 |
| [EGAgent：Agentic Very Long Video Understanding](https://arxiv.org/abs/2601.18157)，2026-01 | 围绕时间标注的实体图组织超长视频证据，由规划与检索工具支持问答 | 实体+时间图也已出现；LongEmo 的重点需要落在情感状态关系与因果证据 |
| [MAGIC-Video](https://arxiv.org/abs/2605.08271)，2026-05 | 统一多模态记忆图 + 长时叙事链，在检索中结合图证据和叙事事实 | 图与人物长程摘要本身不是新意；应验证摘要失真、情感状态原子化与回看纠错 |
| [ReflectWorld-MM](https://arxiv.org/abs/2607.09759)，2026-07 | 实体解析的视听观察，分层情景/语义/程序记忆，用于开放视频流 | 对身份维护与长程记忆很相关；“给感知加历史”不足以构成区别 |

### 2.1 WorldMM：最需要直接比较的通用记忆方法

原文 §3.1 明确有多时间尺度情景图；语义记忆通过候选匹配后由 LLM 决定删除/更新；视觉记忆支持细节核对。它并不是只会静态存 caption 的系统。[方法正文](https://arxiv.org/html/2512.02425v1)

建议对照：固定同一批情感观察与来源，比较通用事件/语义组织和按“主体—对象—时段”维护状态。加入覆盖式轨迹读取、修订/真实变化区分后，看假转折、对象误绑定以及正式题型分数是否改善。保持感知和读取预算一致。WorldMM 的原始系统与同骨干机制重实现应分列。

### 2.2 MAGIC-Video：对“图谱 + 人物叙事”的直接约束

其方法把情景、语义、视觉内容连接，并用跨时段人物/活动叙事补充检索；正文也讨论 caption 没描述的事件无法由后续图遍历或叙事匹配找回的限制。[方法与局限](https://arxiv.org/html/2605.08271v1)

这提示 LongEmo 应保留无情绪标签的原始观察和媒体定位入口。在图里找不到时，区分“没检索到”与“当初未感知”。新的回看必须带来可核对来源；多写一段摘要不能恢复没看到的表情和语气。

### 2.3 整片原生理解也要比较

Google 当前官方文档区分固定采样的视频处理和部分型号的 agentic 视频处理。后者内部就会选择读取视频信息。因此，当实际供应商支持时，应加入该原生能力作为完整系统基线，并记录处理模式与 usage。它不等于已证明在 LongEmo 上更强，第三方代理也不必然开放这些能力。[官方视频理解文档](https://ai.google.dev/gemini-api/docs/video-understanding)

## 3. 情感分析与情感推理方法

| 方法与时间 | 原文任务/机制 | 对 LongEmo 的启发/限制（本轮判断） |
|---|---|---|
| [DialogueGCN](https://aclanthology.org/D19-1015/)，EMNLP-IJCNLP 2019 | 对话情绪识别，用图建模同说话者和不同说话者的依赖 | 人际依赖是长期研究主题；情感图不能只连时间相邻窗口。其原始图不是长视频视听身份系统 |
| [RECCON：Recognizing Emotion Cause in Conversations](https://arxiv.org/abs/2012.11820)，2020/2021 | 对话中定位情绪原因，提供原因与情绪对应数据 | 原因定位应能指回具体事件/对白，不只写流畅心理解释 |
| [SemEval-2024 Task 3](https://arxiv.org/abs/2405.13049)，2024 | 多模态对话情绪原因分析，抽取情绪和对应原因 | 可用于原因模块外部诊断；不可直接把其题型/标签套到 LongEmo |
| [Emotion-LLaMA](https://arxiv.org/abs/2406.11161)，2024 | 多模态 instruction tuning，同时面向情绪识别和推理 | 局部情感专用感知模型的代表；短片分数不能代表整集记忆质量 |
| [AffectGPT / MER-Caption / MER-UniBench](https://proceedings.mlr.press/v267/lian25a.html)，ICML 2025 | 描述式情绪数据、多模态预融合，以及适配自由文本输出的情感评测 | 支持开放情绪描述与多模态线索，而非只存少数标签；可作局部感知对照 |
| [Emotion-LLaMAv2 / MMEVerse](https://arxiv.org/abs/2601.16449)，2026-01，v2 2026-02 | 多视角编码、模态预融合、感知到认知的课程式指令训练；整合多个情感数据集 | 检查人脸局部与场景上下文的取舍；实际模型可用性、输入条件和域适配需复核 |
| [EMO-R3](https://arxiv.org/abs/2602.23802)，2026-02 | 结构化情感思考和反思式 RL 奖励，强调视觉文本一致性与情感连贯 | 训练型结构推理近邻；不是“不训练加一句反思 prompt”就完成复现，也不是长视频检索方法 |
| [AffectSeek](https://arxiv.org/abs/2605.05640)，2026-05 | 对模糊情感问题，进行意图理解、定位、验证、情感判断和解释；提出 VQAU-Bench | 与“长视频中找情感证据”最接近之一，应纳入核心相关工作和主动检索对照 |
| [ECFlow：Why Do Emotions Change?](https://aclanthology.org/2026.acl-long.539/)，ACL 2026 | appraisal 引导的结构生成与图式 RL；情绪原因流图优化变化连贯性和事件一致性 | 对原因与变化关系高度相关；本项目可先测试有依据的 appraisal 字段，避免立即上 RL |
| [OneEmo](https://arxiv.org/abs/2608.06013)，2026-08 | 统一情绪感知、理解、互动，多任务数据、SFT 与 Emo-Chord RL | 本轮补充的较新情感专用模型，适合列入候选；不预设它比通用 omni 更适合 LongEmo |

### 3.1 AffectSeek：不能忽略的长视频情感近邻

正文区分候选时间定位与片段证据验证，Perception-Agent 返回验证片段、情绪及依据，再做可靠性检查；论文也做工具/agent 级消融。因此主动定位、核对和解释情感片段已有直接工作。[方法与消融正文](https://arxiv.org/html/2605.05640v1)

建议保留相同模型和回看片段预算，比较“围绕问题找目标情感片段”和“在可复用记忆中取得全片状态关系、必要时补看”的差异。重点看多阶段轨迹、跨对象并存、反复计数等需要跨段组织的能力；实际是否为 LongEmo 主要失分项仍待题目核验。

### 3.2 ECFlow：区分原因建模与解释修订

ECFlow 用认知评价驱动情绪原因三元组生成，并以情绪原因流图构建结构奖励，强调同人情绪变化和核心事件一致性。[ACL 正文入口](https://aclanthology.org/2026.acl-long.539/)

LongEmo 可以保留“事件如何被人物理解”作为有证据的可选中间表示；核心研究对照则进一步检查：新增后段证据究竟描述新的变化，还是纠正过去的解释，以及下游轨迹是否同步修正。不能仅靠字段名字不同宣称区别，最终需要机制与消融支持。

### 3.3 情感专用模型怎样用

不要让每个短窗都并行跑多个情感专家投票。先把通用 omni 和一个专用模型在同一批真实开发片段上比较：说话人、听者、讽刺/混合情绪、局部强度与证据引用是否更准。若只在某类困难片段上有增益，再考虑定向调用；否则增加模型复杂度没有依据。

AffectGPT、Emotion-LLaMAv2、OneEmo 的论文任务设置提供了候选方向，尚不足以决定最终骨干。检查模型训练数据和 benchmark 来源重合情况，尤其涉及相同影视来源时；这一检查应报告实际重合证据，而不是猜测污染。

## 4. 哪些思想进入新版 plan

| 借鉴来源/问题 | 进入新版的机制 | 首轮如何验证 |
|---|---|---|
| 长视频描述压缩会遗漏细节 | 原始观察与来源永久保留，摘要只导航 | 比较普通 caption RAG 与丰富观察 RAG |
| VideoTree、WorldMM 的多尺度组织 | 原子观察—事件—人物/事情摘要，按粒度读取 | 同内容/同 token 的平铺 vs 图索引 |
| M3-Agent、ReflectWorld 的实体持续性 | 身份库、说话人候选、错绑定可修正 | 身份、说话人和对象错误审计 |
| DialogueGCN 的人际依赖 | 保存说者/听者/目标，关系需要具体依据 | 听者反应题和混合主体消融 |
| 描述式情绪学习 | 线索与情绪候选分层；开放描述后适配标签 | 标签精确率及自由文本题型分数 |
| ECFlow 的 appraisal/一致性 | 可选“事件—人物理解—状态”短链 | 原因依据支持率，去掉 appraisal 对照 |
| AffectSeek 的证据验证 | 有缺口才主动回看，观察问题保持中性 | 同预算的相关性回看 vs 缺口回看 |
| 图和叙事方法的覆盖限制 | 全片轨迹/最大值/次数先做范围覆盖 | 与 top-k-only 对照，测遗漏与最终分数 |
| 旧 plan 的纠错设计 | 状态真实发展与解释修订分开，依赖原子刷新 | 正确→错误、错误→正确及假转折率 |

其中“版本、引用、依赖刷新”是工程保障；“情绪对象、支持与冲突”是表示选择；真正需要论文验证的是这些选择是否改善特定长程情感推理错误，而非堆叠更多名词。

## 5. 暂不放入首轮主线的内容

- 自训练长视频 backbone、GNN 或 RL 控制器：成本较高，尚无当前错误分布支持。
- 每条边一个 verifier、每题多模型大规模投票：会混入额外算力，先做有针对性的核对。
- 全部状态都填写心理理论维度：会鼓励虚构无法观察的内在原因。
- 只靠 VAD/统一强度数值排序：跨人物、情绪和表演风格未校准。
- 跨视频统一图数据库与分布式执行：当前每视频独立事件图即可；按用户最新要求，API embedding 已纳入首版双路召回。

## 6. 建议的阅读与复现顺序

**第一组：最接近当前方案。** WorldMM → AffectSeek → ECFlow → MAGIC-Video。先读表示、更新、检索动作、输入条件与消融，理解哪些设计已被覆盖。

**第二组：感知和身份。** M3-Agent、ReflectWorld-MM；AffectGPT、Emotion-LLaMAv2、OneEmo。先评估是否有适配本项目的可运行局部能力。

**第三组：基线和扩展。** LLoVi、VideoTree、MovieChat、LongVILA、VideoRAG、EMO-R3。用于解释路线差异，并按资源选择复现范围。

论文之外，运行前核查 [Google 视频理解](https://ai.google.dev/gemini-api/docs/video-understanding)与 [OpenRouter 视频输入](https://openrouter.ai/docs/guides/overview/multimodal/videos)的接口约束；通过实际短素材验证代理行为。接口相似不等于音频、fps、文件上传或 provider routing 的能力一致。

## 7. 结论的证据等级

- **已由原始来源支持：** 各论文所提出的核心模块及其任务范围，官方 API 的文档说明。
- **基于文献与旧 plan 的研究判断：** 对象绑定、完整证据覆盖、错误修订最值得作为本项目的实验重点。
- **尚未验证：** 新方法相对旧代码/基线的实际提分、当前最佳模型、最优采样率、图比平铺更优、训练是否必要。

后续应把第二类判断变成可证伪的实验，不把它们提前写成实验结论。


## 实施更新

用户已选择事件图上的结构化语义 + embedding 双路检索，主推理模型升级为 GPT-6 Astra。Gemini Embedding 2 已通过 3072 维真实接口测试，并作为主向量编码器；先前 E5 本地检查仅保留为可选诊断。实现和试验记录见 `experiments/zyf/README.md`；调研表内的进一步消融不代表首轮均已运行。
