# 三层级消融实验与论文分析计划

本研究把三个分支定义成一条清晰的能力递进链。三者必须使用同一题单、同一视频版本、同一 20 秒核心窗口与 2 秒上下文、相同抽帧／字幕／音频观察配置、同一 GPT-6 规划与回答模型、同一 Gemini Embedding 2、同一官方 judge 和相同重试规则。每个分支使用独立的运行目录、记忆文件和向量缓存；任何缺失题都保留在覆盖率分母并单独报告，已评分均分不纳入缺失题，不能把服务失败当成零分，也不能用另一分支的答案补齐。

| 层级 | 感知与存储 | 问题端检索 | 主要隔离的因素 |
|---|---|---|---|
| `noevent` | 只保存固定窗口记录、人物、观察、动作／对象、显式信号和原始时间证据；不生成事件、状态、关系或跨窗口连续性 | 在窗口记录上做 BM25＋Embedding 双路召回，按绝对时间排序后回答 | 没有事件归并、事件级去重、状态变化和关系导航的窗口对照 |
| `base` | 构建经过校验的事件图，事件拥有情感状态、观察引用、人物／对象和关系 | 一次性从完整图上双路召回，沿显式关系和同人物相邻事件扩展，在固定上下文预算内回答 | 事件表示、跨窗口合并、相邻事件导航和关系证据的增益 |
| `method` | 与 `base` 使用同一份冻结事件图和同一向量索引 | 先从完整图定位锚点，再按人物／目标／关系／时间流逐页披露所需事件，达到覆盖或预算停止条件后回答 | 在已有事件图上，渐进披露是否比一次性暴露更能保留长时间证据并减少噪声 |

因此，核心差分按两步解释：`noevent → base` 衡量“事件化记忆”的贡献，`base → method` 衡量“完整事件图上的渐进式检索”的贡献，`noevent → method` 是端到端总增益。若 `base` 与 `method` 重新构图或采用不同感知模型，结果只能作为混合提供方比较，不能把差值归因于检索策略；正式主表固定同一图快照，新的感知实验另列来源。

## 先冻结干净的三路对照

已有 60.24 分来自题型路由实验：轨迹题渐进披露，强度比较与推理题使用完整图证据。它可以与同题 base 作历史比较，但不能代替纯渐进式方法的三层消融。schema v2 的动作／对象／显式信号字段是在该成绩之后加入，尚无对应的新三路成绩；不能把旧分数标成 schema v2 的效果。正式实验冻结同一份 schema v2 事件图、索引和题单，分别运行 base 的一次检索和 method 的纯渐进披露；题型路由版另列附加实验。

`noevent` 的严格版本只允许当前窗口的媒体和仅用于身份对齐的人物索引；人物索引不表达跨窗连续性，`emotion_cues` 也只表示窗口内可观察的情感线索。它不能接收前几个窗口摘要或隐含的 `preceding_windows`。三路必须统一证据预算（当前协议为 48000 字符）、窗口采样和音频配置；若要研究“给 noevent 相邻上下文”的影响，另建 `noevent+context` 变体，不能混入主表。

## 要保存的结果

每个分支都输出总体、三种 episode 题型、分剧和逐题首个有效分数，并同时保存以下审计字段：

1. **准确性与覆盖率。** 报告归一化总体均分、题型均分、二元确定题与解释题的分数、已评分／总题数、有效预测率、缺失原因和内容过滤／认证／超时数量。总体同时给出按题等权和按视频等权两种口径，主结论使用预先声明的题等权口径。
2. **配对差值与不确定性。** 只在三个分支都有首个有效评分的同一题上计算 paired delta；按视频聚类并按剧名分层 bootstrap 10,000 次给 95% 置信区间，并报告正负变化题的数量。二元题补充 McNemar 检验，避免只比较不同覆盖集合的均值。
3. **证据召回。** 从 trace 统计人物／情感目标是否命中、所问时间范围覆盖比例、轨迹阶段覆盖、比较题候选覆盖、计数候选去重、因果链／显式关系命中、引用 ID 有效率和截断遗漏。gold 只在离线审计阶段用于标注，不进入任何运行提示词；先人工审计分层抽样，再报告自动代理指标。
4. **渐进披露行为。** 对 `method` 记录初始锚点数、每题披露轮数、披露事件数／观察数、时间流与关系流比例、重复事件数、停止原因、最终上下文字符数和 `retrieve_more` 请求是否有效。与 `base` 对比同等答案质量下的上下文长度、token、调用次数、延迟和成本。
5. **错误归因。** 将低分题按“感知漏检／人物误合并或误拆／事件边界或重复计数／状态或目标错误／关系或因果错误／语义召回漏项／Embedding 召回漏项／时间覆盖不足／上下文截断／回答组织／解析或服务失败”标注，可一题多标签；保留原始窗口、排名和回答 trace，不能只凭最终答案猜原因。
6. **长视频伸缩性。** 按视频时长、窗口数、事件数、问题要求的阶段数和候选数量分桶，画出分数与上下文预算、token、延迟的关系。重点观察长视频中 `base` 的一次性上下文截断是否增加，以及 `method` 是否用较少披露事件保持必要时间覆盖。

统计时把题目视为嵌套在视频和剧集中的观测：主结果给题等权均分，但置信区间和显著性检验按视频聚类 bootstrap（必要时再按剧集分层），并同时报告宏平均视频分数。否则同一视频的多道题会让区间虚窄。除了三路主表，还可以预注册以下小消融：仅 BM25、仅 Embedding、去掉关系扩展、固定页大小、不同锚点数、关闭题型路由，以及 `base` 的证据预算匹配版。所有小消融使用同一图快照和题单，结果放在附录，避免把多个自由度包装成一次增益。

## 推荐的实验顺序

先冻结 50 题 pilot 的题单，再在该题集上让三分支共享题单和配置，检查三种记忆的窗口覆盖、事件字段隔离、证据 ID 有效性、无重复评分和调用账本。pilot 通过后冻结代码／模型／题单哈希，再跑同一 520 题子集；最后才扩展到 558 题全集。`noevent` 的感知构建与 `base`／`method` 的事件构建可以并行，但 `base` 和 `method` 的回答必须读取同一份完整图，不能在 `method` 运行中重写图谱。

当前一次 50 题 pilot 的执行量约为 21 个视频、约 1,200 个 20 秒窗口。数据恢复完成后，按 6 个视频构建 worker 的 API pipeline，先用一个视频完成端到端 smoke，再放开其余视频；通常需要数小时完成感知，回答、Embedding 索引和官方评分再需要约 0.5–2 小时。网络、模型限流或内容过滤会扩大范围，运行目录中的 `process.json`、窗口完成数和 `calls.jsonl` 是实际进度依据，不能用启动时间推断完成。

## 论文中应突出和应避免的表述

论文主线应强调：长视频情感问题的难点不是只识别一个局部情绪，而是要在**人物—目标—时间—证据**四个维度保持一致；事件图把重复窗口归并为可追踪发生、把状态变化和关系证据显式化，渐进检索再把完整图转化为按问题需求展开的时间流，从而在有限上下文预算下覆盖跨段证据。三层消融分别回答“要不要事件表示”和“有了事件图后如何读图”两个问题，避免把结构化记忆和检索策略混成一个黑盒增益。

文章中应把贡献写成可检验的机制假设：`noevent → base` 若在跨阶段轨迹、因果和重复计数题上提升，支持事件归并、状态变化和关系证据的作用；`base → method` 若在长视频和多阶段问题上以更少上下文保持或提高得分，支持“完整图先定位、按需披露时间流”的检索作用。若强度比较仍落后，应把它作为感知对显式动作／数量／比较信号不足的限制，并报告具体漏检类型，而不是声称图检索已经解决该问题。主文避免宣称通用视频理解 SOTA、真实心理状态或因果真值；模型、服务、采样预算、覆盖率和失败原因全部随结果公开。

可以声称的是在固定 LongEmoBench 协议上的配对经验增益、证据覆盖和效率变化；不能据此声称通用视频理解 SOTA、真实心理状态或因果真值，也不能把不同感知提供方、不同采样预算或不同覆盖率下的分数直接当作结构贡献。所有主表保留模型／服务／采样来源、缺失范围和 judge 配置，负结果与失败原因同样报告。


实际 base 的 seed 来自完整事件图，相邻事件和显式关系是检索后的扩展；不能将其描述为只能访问局部图。noevent → base 改变了记忆表示、跨窗合并和导航，是这一组能力的组合消融；若要单独归因于某个字段或关系，需要同图去边／去状态等子消融。对窗口方法不额外禁止基于已检索证据进行跨窗推理，主区别是感知存储和可用检索结构。
